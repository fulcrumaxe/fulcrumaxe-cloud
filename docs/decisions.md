PRs that touched `apps/`, `packages/`, `sites/`, `flake.nix` or `.github/`.

## Entries

1. **Row-level security is `FORCE`d on every tenant table, not just enabled.** Without `FORCE`, the table owner (the role migrations run as) bypasses the policies. — `#12` — still true: `packages/db/migrations/0001_core.sql` has a `FORCE ROW LEVEL SECURITY` statement for every tenant table.
2. **Money columns are `numeric`, never a float.** Floating-point rounding error is unacceptable for anything that ends up on a bill. — `#11` — still true: `packages/db/migrations/0001_core.sql`'s spend columns are `numeric(10, 2)`/`numeric(10, 4)`.
3. **Partner isolation is three levels (partner / account / user), not two.** A partner's own staff, the accounts it resells to, and end users each need a distinct trust boundary. — `#13` — still true: `packages/db/migrations/0200_partners.sql` defines the `partner_user` role and partner-scoped tables.
4. **CI runs the check inside the Nix dev shell, on the same toolchain a developer has.** The job needs Nix, Postgres and Playwright browsers exactly as a local `nix develop` provides them. — `#14` — still true, with the runner choice since changed: `.github/workflows/ci.yml`'s `check` job runs `nix develop .#ci --command bash scripts/check.sh`, and its `runs-on` is `ubuntu-latest` on a public repository and `self-hosted` (or the `CI_RUNS_ON` variable) on a private one.
5. **Design tokens are the one source of visual values; no hardcoded colours or lengths outside the token files.** Keeps `apps/web` and site-kit visually consistent and swappable for a white-label palette. — `#39` — still true: `packages/design/src/` holds the token and stylesheet-builder modules the other two consume.
6. **The workspace importer accepts only a source-control archive tar, never the raw working tree.** A tar built by reading the object store structurally cannot contain untracked `.env` files, regardless of which user runs the importer. — `#49` — still true: `apps/workspace/import/import.mjs` takes a `--tar` argument and verifies its recorded commit id, with no working-tree-path mode.
7. **The importer's allowlist is exact per-file, not a blanket glob.** A blanket `core/**`-style glob would also select `.js.map` siblings that the secret/dotfile scanner flags unconditionally, refusing the whole import. — `#95` — still true: `apps/workspace/import/allowlist.txt` lists `core/*.js`, `sdk/**`, `runtime/**` and `apps/themes/**` per-extension rather than as directory globs.
8. **`core/automerge-bootstrap.js` is excluded from the workspace import, even though it's a real upstream file.** The importer's own unconditional rule refuses any path containing "automerge"; the file was left out rather than weakening that rule. — `#95` — still true: `apps/workspace/import/checks.mjs` has the unconditional "automerge" substring rule, and `apps/workspace/import/allowlist.txt` doesn't list the file.
9. **The runner's outbound network policy is deny-by-default and never returns a wildcard host.** A per-role, per-phase allowlist of exact hostnames is safer for a sandbox running arbitrary agent code than a broad egress rule. — `#50` — still true: `packages/runner/src/networkPolicy.ts` builds an exact-host allowlist and documents that it never returns a wildcard rule.
10. **Billing writes to `accounts` go exclusively through `platform_ops`; `app_user` has no INSERT/UPDATE on that table at all.** A tenant session should never be able to change its own plan or status directly. — `#53` — still true: `packages/billing/src/accountLifecycle.ts`'s functions run through the platform-privileged connection.
11. **Decision-policy dial history is append-only — every change is a new versioned row, never an edit.** Makes "what was the setting at time T" answerable and keeps an audit trail that can't be silently rewritten. — `#54` — still true: `packages/db/migrations/0400_decisions.sql` keys `decision_settings` on `(account_id, repo_id, decision_type, version)` with no UPDATE/DELETE grant to `app_user`.
12. **Customer model keys are envelope-encrypted: a random per-row data key, wrapped by a versioned platform KEK, both carrying AEAD additional data.** Limits the blast radius of a single compromised KEK version and binds ciphertext to the row it belongs to. — `#55` — still true: `packages/model-connection/src/crypto.ts` implements `seal`/`open` on this shape.
13. **The decision resolver `decide()` is pure and never reads `customerProximity`/`dataSensitivity`.** Those fields exist for humans reading the catalogue, not for the resolver's own logic, to keep the resolver's behavior fully determined by class and preset. — `#60` — still true: `packages/decisions/src/decide.ts` has no reference to either field name.
14. **`account_members` and `invitations` gained role-derived, per-command RLS policies instead of an `account_id`-only check.** Any session inside an account could otherwise re-role or delete any row, including the owner's. — `#75` — still true: `packages/db/migrations/0005_account_members_role_gate.sql` defines `current_member_role()` and the owner/admin/member-scoped policies.
15. **CSRF is decided once, in middleware, by which credentials are present on the request — before any route handler runs.** Centralizes the check instead of re-implementing it per route. — `#82` — still true: `apps/web/lib/shell/csrf.ts`'s `csrfStep` is the first step registered in `apps/web/middleware.ts`.
16. **`audit_log` writes go through a `SECURITY DEFINER` function (`audit_write`) that stamps actor/account/timestamp itself; `app_user` lost its INSERT grant entirely.** The RLS-only policy let any session forge `actor`, `action` or `created_at`, which had already been exploited twice. — `#91` — still true: `packages/db/migrations/0008_audit_log_append_only.sql` revokes INSERT from `app_user` and defines `audit_write`.
17. **Agent runs are dispatched through an `ExecutionTarget` seam, resolved from a database column, never from an environment variable.** Keeps the run backend swappable and prevents an environment difference from silently picking a different execution target. — `#85` — still true: `packages/runner/src/executionTarget.ts`'s resolver reads `repos.execution_mode` and fails closed on an unregistered mode.
18. **Model routing is a Postgres-backed table (role, size) → model, not a hardcoded map.** Lets a routing change ship as a data update (with a proposal/promotion workflow) instead of a code deploy. — `#88` — still true: `packages/db/migrations/0010_model_routing.sql` defines `routing_tables`/`routing_rows`, and `packages/model-router/src/route.ts` reads them.
19. **`ModelBadge` was built and tested standalone, not wired into a run page.** The run-listing page it was meant to register into doesn't exist yet in this repo. — `#88` — still true: `apps/web/app/(team)/runs/_components/ModelBadge.tsx` exists, nothing outside its own test imports it, and `apps/web/package.json` does not depend on `@fx/model-router`. Runs are shown by the workspace's Runs app instead (`apps/workspace/apps/runs/`).
20. **Role-scheduling settings are a plain service module first; the page and API route came later and call it.** The UI was a separate task, which kept the read/write contract independently testable. — `#89` — superseded in part: `packages/core/src/role-settings/setMode.ts` is still the writer, and `packages/api/src/routes/roles.ts` now exposes it under `/api/v1`, with the workspace's Roles app (`apps/workspace/apps/roles/`) on top.
21. **Migrations run under a Neon-shaped, non-superuser owner role, proven by a dedicated CI check rather than assumed.** Hosted Postgres never grants the migration role superuser, and the chain previously aborted on `ALTER ROLE ... NOSUPERUSER`, which itself needs superuser to run. — `#92` — still true: `packages/db/scripts/test-neon-shape.sh` is wired into `scripts/check.sh`.
22. **A signed-in user gets a fresh session id on every sign-in, and a stored `session_epoch` lets "sign out everywhere" invalidate every other still-valid session.** A cryptographically valid, unexpired cookie shouldn't remain usable after the user explicitly signs out of all sessions. — `#96` — still true: `packages/core/src/auth/session.ts` mints a new `sid` per sign-in, and `packages/db/migrations/0604_session_epoch.sql` adds the `users.session_epoch` column it checks against.
23. **`idempotency_keys` is numbered `0600`, not the next sequential slot, to avoid colliding with an already-reserved migration number elsewhere.** — `#82` — still true: `packages/db/migrations/0600_api_core.sql`'s header records this numbering choice.
24. **Every factual sentence on a site-kit site is a gated `Claim`, not typed HTML — the build refuses to write output if any claim is unverified.** Keeps a public, unreviewed-by-a-human page from ever shipping an unverified product claim. — `#98` — still true: `packages/sitekit-claims` holds the `gateSite` gate. The one-off marketing site that first used it was archived on 2026-10-05 and is no longer built.
25. **The cloud workspace build profile strips Automerge/CRDT and other non-cloud features by filtering the shell's static import graph, rather than shipping the full desktop bundle.** Removing dead code paths this way also lets the idle-network test prove zero background activity for the features that were dropped. — `#100` — still true: `apps/workspace/build/profile.mjs` walks `apps/workspace/profiles/cloud.json`'s `drop_core` list against the shell's import graph.
26. **The GitHub-proxy forward host is an operator-configured allowlist (a fixed suffix), not any syntactically-valid hostname, and its resolved address is checked on every call rather than accepted on hostname shape alone.** A syntax-only check accepts a hostname the operator never configured, and doesn't catch one that resolves to an internal address. — `#113` — still true: `packages/runner/src/githubForwardConfig.ts`'s `loadGithubForwardConfig` requires a configured suffix, and `packages/runner/src/firewallPolicy.ts`'s `buildFirewallPolicy` resolves the host through `packages/net-guard/src`'s `resolveChecked` before building a policy.
27. **`accounts.status` is a column the database derives from independent per-holder marker timestamps, not a value application code writes directly.** Three separate parties (owner, partner, platform) can each want to stop an account, and a single `status` column can only ever record one of them at a time. — `#93` — still true: `packages/db/migrations/0606_derived_account_status.sql` adds the `accounts_derive_status` trigger and rejects a direct `status` write that disagrees with the derived value.
28. **A new migration file must sort strictly after every migration already on its PR's base, checked by a dedicated CI script rather than left to reviewer attention.** Filename order is what `migrate.ts` actually applies; a file numbered out of merge order can apply in an order nobody reviewed. — `#118` — still true: `packages/db/scripts/check-migration-order.sh` is wired into `scripts/check.sh` right after `test-neon-shape.sh`, and fails closed (exit 2) if it can't resolve the base ref.
29. **A subscription's activation unlocks the workspace; there is no separate licence-activation flow in cloud.** The fulcrumaxe-os licence-activation module doesn't fit a hosted subscription product, and the gate it replaces is cosmetic only — the server already denies runs for a non-active account regardless of what the client renders. — `#162` (D#37 WS-L1 owner ruling) — still true: `apps/workspace/profiles/cloud.json`'s `app_modules` no longer lists `activation`, and `apps/web/lib/shell/session-routes.ts`'s `meResponse` derives `workspace_access` from the account's billing status.
30. **The GitHub proxy gates every git smart-HTTP request by its literal URL endpoint, not by which service the request's target maps to.** Gating on `service` alone let any method (including PUT/PATCH/DELETE) reach `git-upload-pack` once the target parsed as that service, so a non-GET/POST request could reach GitHub with a minted credential. — `#160` — still true: `packages/gh-policy/src/decide.ts` denies `info/refs` to anything but GET/HEAD and `git-upload-pack`/`git-receive-pack` to anything but POST, keyed on `pathTarget.ts`'s `endpoint` field.
31. **The post-merge check's outcome comes from deterministic rules, never from the tester's own verdict.** A model that drives a browser can claim more than it showed. — `#842` — still true: `packages/pipeline/src/verify/rules.ts` turns the tester's answer into a row outcome, rewrites a `pass` that has no page fact or number, no undo check or no reload to `unverified` (a journey marked view only, such as a filter or a reading, needs no reload, #982), and judges the signed-in account only from a value the runner's trusted verify server wrote (that server's own `signed_in_as_unavailable` marker is the one other word it accepts, see entry 36).
32. **The verify browser the tester drives is a closed table of small tools with no script execution, no free-form address and no selector.** Page text is hostile input, so the model gets only what it needs to click through a journey. — `#853` — still true: `packages/fx-runner/src/verifyBrowser/server.ts` builds both the advertised tool schemas and the argument checks from one `TOOLS` table, and fences every page text it returns as untrusted.
33. **The merge gate counts `fx-gate1` only when the cloud's own App posted it.** A status posted by a person, another token or another app proves nothing about who ran the check. — `#805` — still true: `packages/pipeline/src/review/gate1Creator.ts` reads who posted the status, and `packages/pipeline/src/review/mergeGateRun.ts` stops the gate with `gate1_status_foreign` for any other poster.
34. **A direct merge and the merge queue's slot exclude each other per repository through a lease, not through a cleanup job.** Two paths that both merge on one repository could otherwise race; a lease past its time is dead, so a crashed holder blocks nothing for long. — `#700` — still true: `packages/pipeline/src/mergeQueue/mergeLease.ts` takes both checks under one advisory lock keyed on the repository.
35. **A fix round that added no commit does not spend the runner's post-build check.** The cloud already ends such a round on its own no-commit path whatever the check says, so running the check (up to its time limit) only delays it. — `#926` — still true: `packages/fx-runner/src/daemon/jobHandler.ts` skips the check with the closed reason `no_change` only when the job is a `review_fix` round that continues a branch and the workspace tip still equals the commit it started from, and a round that did push is judged as before. The round kind is signed by the cloud (`packages/runner/src/targets/jobIssuer.ts`, `packages/runner-protocol/src/job.ts`), never taken from the runner, and `packages/db/migrations/1018_run_checks_reason_no_change.sql` lets `run_checks.reason` hold the new value.
36. **An expired verify sign-in parks the post-merge check instead of failing it as the wrong account.** The app drops a session on its own side while the cookie in the runner's saved sign-in still looks valid there, so a person had to sign in again and press "Verify again" for what was not a product failure. — `#947` — still true: `packages/pipeline/src/verify/rules.ts` parks a row only on the verify server's own marker (never a model-written value), `packages/worker/src/verifyRun.ts` holds it with `needs_sign_in` for at most 24 hours and three parks, and `packages/db/migrations/1020_verify_sign_in_expiry.sql` is the one place `verify_rows_guard` allows `running` back to `pending`.
37. **The cloud's own pull requests may ask for the front of GitHub's merge queue, once per repository per window, and a refusal falls back to a plain enqueue.** A jump makes GitHub rebuild every entry already in progress, so the rule is narrow and the queue's own rules must never be skipped. — `#944` — still true: `packages/pipeline/src/review/queueJump.ts` allows it only for a repository in `FX_GATE1_ATTEST_REPOS` and not inside `FX_QUEUE_JUMP_MIN_MINUTES` of the last one, `packages/github/src/mergeGateGraphql.ts` pins the jumping enqueue as a document of its own with the flag fixed in its text, and `packages/pipeline/src/build/githubMergePort.ts` retries once as a plain enqueue when GitHub refuses it for any reason except a moved head.
38. **The workspace's start theme is embedded into `theme-manager.js` at build time, and only the theme in use is fetched.** The cold-start request count has a budget that counts what the shell fetches by itself, and eight theme files had pushed it over. — `#955` — still true: `apps/workspace/build/profile.mjs`'s `substituteDefaultThemeData` writes the profile's default theme JSON into the shipped file, and `apps/workspace/build/budget.mjs` holds the cap that `apps/workspace/e2e/boot-budget.spec.ts` counts live. The cap on static requests was raised from 130 to 135 in #1020 when the Team app joined the boot set.
39. **The workspace shows a role's mode and the verifier roles in words, never as the raw code.** A code such as `feature_critical` or `deploy-verifier` means nothing to the person reading the screen. — `#937`, `#950` — still true: `apps/workspace/apps/roles/roles-autonomy.js` holds one `MODE_TEXT` map that both the mode dropdown and the merge copy read, and `apps/workspace/apps/runs/runs-detail.js` and `apps/workspace/apps/pipeline/pipeline-insight.js` name `deploy-verifier`, `proposal-verifier` and `discovery-analyst` in words.
40. **A check-fix round may change the failed test files that import changed code, and only those.** A failed test file that imports changed code is counted as inside the change, and the round that fixes it should not be refused for touching it. — `#976` — still true: the cloud adds those files to that one round's signed job `scope` (`packages/worker/src/checkFix.ts`, `packages/runner/src/targets/jobIssuer.ts`), only plain test-shaped paths (`packages/runner-protocol/src/acceptanceScope.ts`), at most 20 over the whole chain of rounds, and never to the Spec itself. `packages/runner-cloud/src/done.ts` holds the pull request to the Spec's list plus exactly those files. The failed-file names are read from the check summary only above the `CHECK_HEADER_END` line, and only when the cloud's own record says the runner is at protocol 19 or later (`packages/runner-protocol/src/messages.ts`), so an older runner's output is never read as header.
41. **Merge-queue rollups wait only on an entry's own merge, and only when the live queue settings allow it.** An entry that skipped the suites because an entry on top of it might pass would be reported green on a guess. — `#939`, `#959` — still true, and dormant until `ROLLUP_ENABLED` is `true`: `scripts/ci/rollup-position.mjs` ends an entry that has another on top of it as a success only once its own pull request is merged, and runs the suites in full on any doubt (an API error, a cloud-built entry in the chain, the wait cap), and it waits only while the branch's merge-queue rule is `HEADGREEN` with a response timeout of at least 150 minutes (`.github/workflows/ci.yml`).
42. **A plane merge order the gate blocked for an overlap starts the update round from the runner's facts, and the facts are only a hint.** A wrong claim from a runner then costs at most one bounded round and never widens what the cloud reads. — `#963`, `#964`, `#965`, `#979` — still true: a runner with the `overlap_facts_v1` capability attaches a closed verdict to its merge check (`packages/runner-protocol/src/job.ts`, `packages/runner-protocol/src/messages.ts`), and `apps/web/lib/mergeQueueWait.ts` starts the round only when every reason the gate gave is an ordering one and includes `overlap_unreviewed`; a missing verdict stops the order with `overlap_facts_missing` (`apps/workspace/apps/pipeline/pipeline-insight.js`). The gate leaves one answer per merge order (`packages/pipeline/src/review/mergeGateRun.ts`), so a second order on the same head can be rerouted too.
43. **The engine halt is a marker only a person can clear, written through two `SECURITY DEFINER` functions rather than a table grant.** A halt has to beat a decision or a command that is in flight, and an automated actor must not be able to lift it. — `#992` — still true: `packages/db/migrations/1031_engine_halt.sql` makes `app_user` read-only on `engine_repo_controls`, puts `engine_halt_set` and `engine_halt_clear` under `engine_halt_definer` (an owner or admin session only), and has `BEFORE INSERT` triggers on `engine_decisions` and `engine_commands` take the marker `FOR SHARE`; `packages/db/scripts/test-neon-shape.sh` pins the five functions and the role.
44. **A command to the engine is signed by the cloud and judged again on the runner, from a closed set of seven.** The engine runs on a customer's own machine, so the runner cannot trust the wire and the cloud cannot trust the machine to be the one it expects. — `#998` — still true: `packages/runner-protocol/src/engineCommands.ts` holds `ENGINE_COMMAND_KINDS` and the strict schema, `packages/runner/src/targets/jobIssuer.ts` signs with the job-signing key, and `packages/fx-runner/src/engineBridge/commands.ts` refuses a command whose signature, runner, repo, expiry or sequence is wrong before the engine sees it. The hosted Team Lead adds one more refusal of its own: a second answer for an ask it already answered is `already_answered` and never reaches the engine (`COMMAND_REFUSALS` in the same protocol file, #1011).
45. **The runner keeps no list of repositories the engine bridge may use; the cloud's list is the only one.** A list kept on the machine could drift from what the account actually paired. — `#1010` — still true: `packages/fx-runner/src/commands/engineBridge.ts` writes a repo to the settings file only after the cloud's answer names it, and `packages/fx-runner/src/engineBridge/daemon.ts` starts a repo's loops only while the cloud's `allowed_repos` still holds it, and a list nobody renewed in 25 minutes (`ALLOWED_MAX_AGE_MS`) no longer counts (#1036).
46. **Engine figures are information, never spend.** What a person's own engine costs is priced by the cloud for display, and no cap, reservation or envelope may read it. — `#1003` — still true: `packages/core/src/engine/read.ts` exposes `engineApiEquivalentUsd` and returns `total_api_equivalent_usd`, the `engine_api_equivalent_usd` field lives in `packages/spend/src/usage.ts` and `packages/core/src/stats/read.ts` beside the real budgets, and the stats read keeps it out of `metrics`.
47. **A machine is linked to an account by a code the person types, never by a link.** A link that filled the code in would let anyone who can send someone a link get their own machine approved with one click. — `#1035` — still true: `apps/web/app/link/page.tsx` reads nothing from its address and `apps/web/app/link/LinkForm.tsx` starts empty, `packages/runner-protocol/src/deviceFlow.ts` makes `confirm` the literal `true` for an approval and puts a fixed warning written by the cloud beside the machine's facts, and `runner_device_approve` in `packages/db/migrations/1037_device_registration.sql` creates the runner with no repositories.
48. **The typed code is stored as a keyed hash, and the feature is off without the key.** The code has only about 35 bits, so a plain hash of it would be easy to guess from a leaked table; the machine's own device code is 256 bits and a plain SHA-256 is enough. — `#1034` — still true: `hashUserCode` in `packages/runner-cloud/src/deviceFlow.ts` is HMAC-SHA256 under `FX_DEVICE_CODE_KEY`, `requireKey` answers 503 `not_configured` when it is missing or under 32 bytes, and `packages/db/migrations/1037_device_registration.sql` says so in its header.
49. **The hosted Team Lead applies a cloud command at most once, over restarts too.** A command starts or stops an agent, and a host can crash between claiming a command and answering it, so a restart must not repeat one. — `#1009` — still true: `packages/fx-runner/src/engineHost/hostInbox.ts` claims by renaming the file before anything is applied and writes an outcome without replacing one, and `packages/fx-runner/src/engineHost/ticks.ts` never sends a command whose outcome already exists and settles what a host exit left queued or in flight.
50. **The engine's own events file and the engine host's file each have their own cursor, and neither can put events into the other's session.** Two files feed one upload stream, and a line in one that claimed the other's engine instance id would otherwise take over that session. — `#1044` — still true: `createBridgeTails` in `packages/fx-runner/src/engineBridge/daemon.ts` gives each tail its own cursor file and an owner check on every engine instance id, `EngineTail` in `packages/fx-runner/src/engineBridge/tail.ts` drops a line that names the other's instance as a schema drop (the cursor still moves past it), and the host's events carry no source ages, so they never speak for the sources the engine reads.
51. **A merge-queue run is scoped by the whole group, and any doubt answers `full`.** An entry in the queue is tested with everything ahead of it, so its scope has to cover that range, and a scope guessed from too little would let a change skip a suite it needs. — `#1048` — still true: `classifyMergeGroup` in `scripts/ci/affected.mjs` reads the commits from the target branch to the group's head through the compare API, reads each pull request's labels, and answers `full` for a commit with no `(#N)`, a failed read, an event base that is not in the range or `ci:full` on any pull request; `.github/workflows/ci.yml` narrows only `workspace-e2e` this way and `check` keeps its full suite on a queue run.
