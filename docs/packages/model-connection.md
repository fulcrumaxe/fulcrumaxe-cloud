# model-connection

`@fx/model-connection` is the "bring your own key" package: it lets a tenant store their own AI Gateway or Anthropic API key, validates it against the real provider before ever writing it, encrypts it at rest with envelope encryption, and exposes the narrow read/write/test/remove/mark-broken surface everything else in the platform uses instead of touching key material directly. It has no HTTP route of its own in this package — it is a library other tasks wrap.

## What it does

Four principal-scoped functions cover the whole lifecycle: `connect(ctx, { provider, key })` (`packages/model-connection/src/connect.ts`) validates and stores a new key or rotates an existing one; `getStatus(ctx)` (`summary.ts`) returns the account's connection status without ever returning key material; `test(ctx)` (`validate.ts`) re-validates the stored key against the provider; `remove(ctx)` (`remove.ts`) deletes the row outright. `markBroken`/`markBrokenWithClient`/`createConnectionStatusPort` (`markBroken.ts`) are the write-side entry points other packages (for example `@fx/runner`'s key-failure handling) use to flag a connection broken on a 401/403 without depending on this package's full surface. `markBrokenWithClient` also emits a `model_connection.broken` domain event (`@fx/core`'s `emitDomainEvent`, `#173`) on the same transaction client as its two status-column updates, so the event and the status change commit or roll back together. Every change made by the connection's own functions (connect, test, remove) also emits `model_connection.changed` (`{ state: ok | broken | unvalidated | removed }`) in the transaction that made it (`validate.ts`, `remove.ts`). The runner's 401/403 path (`markBroken`) emits only `model_connection.broken`, not `.changed`; an open Onboarding window listens for both, so it re-reads either way; onboarding step 1 is derived from that current state, not stamped once.

Every one of the four principal-scoped functions takes a `ModelConnectionCtx`: an `app_user` `pool` (every read/write of key material goes through tenant row-level security on this), a `platformOpsPool` (the only role allowed to write `status`/`last_validated_at`/`last_error_code`), an injectable `httpClient`, and an injectable `kek` (`KekSource`).

## Public surface

Everything `packages/model-connection/src/index.ts` re-exports: `types.ts` (`Provider`, `ConnectionStatus`, `ConnectionStatusView`, `ModelConnectionCtx`, `Principal`, `isAnthropicProviderEnabled`, `buildAad`), `errors.ts` (`NotFoundError`, `ForbiddenError`, `InvalidModelKeyError`, `DecryptionFailedError`), `kek.ts` (`KekSource`, `envKekSource`), `crypto.ts` (`KekAad`, `Sealed`, `seal`, `open`, `fingerprintOf`), `httpClient.ts` (`ValidationRequest`, `ValidationOutcome`, `ValidationHttpClient`, `fetchValidationHttpClient`), `connect.ts` (`ConnectParams`, `connect`), `remove.ts` (`remove`), `summary.ts` (`getStatus`), `validate.ts` (`test`), and `markBroken.ts` (`BrokenConnectionCode`, `ConnectionStatusPort`, `markBroken`, `markBrokenWithClient`, `createConnectionStatusPort`).

## How it works

**Envelope encryption** (`packages/model-connection/src/crypto.ts`). `seal({ kek, aad }, plaintext)` generates a fresh random 32-byte data key (DEK), encrypts the plaintext with it under AES-256-GCM with a random nonce, then wraps that DEK under the caller-supplied `kek` with its own separate AES-256-GCM nonce. Both layers are bound to the same additional authenticated data (`aad`). `open` reverses this and throws `DecryptionFailedError` — never a raw `node:crypto` error — on a tampered ciphertext, a wrong KEK version, or the wrong `aad`; the GCM auth tag length is pinned explicitly (`authTagLength: 16`) so a short or malformed tag is rejected before decryption is attempted, not silently truncated. `fingerprintOf(plaintextKey, kek)` computes an HMAC-SHA256 over the plaintext key, keyed by an HKDF-derived key that is cryptographically distinct from the KEK's own AES key (`fingerprintKeyFrom`, derived via `hkdfSync` with info string `model_key_fingerprint`) — not the KEK directly — truncated to its last 4 hex characters. This fingerprint is display-only; it is never used anywhere in this package to decide whether two keys are "the same."

**Key custody.** The platform key-encryption key (KEK) is supplied through the `KekSource` interface (`packages/model-connection/src/kek.ts`), never hardcoded. The concrete implementation, `envKekSource`, reads a versioned key from the environment: `FX_KEK_V{version}`, base64-encoded, required to decode to exactly 32 bytes, with the current version read from `FX_KEK_CURRENT_VERSION` (default `1`). Each stored connection records the `kek_version` that wrapped its data key, so the platform can rotate its own root key over time without re-encrypting every existing row. This module's own comment notes the KEK is scoped to model connections specifically — `buildAad` binds every ciphertext to `purpose: 'model_key'` — and is not a platform-wide secret shared across other secret categories. The code shows no other place the raw KEK bytes are read from or written to; there is no code path in this package that logs, returns, or otherwise persists the KEK itself.

**What's stored, what isn't.** `connect` (`packages/model-connection/src/connect.ts`) validates a submitted key against the real provider through the injectable `httpClient` *before* any encryption or write happens; a `rejected` outcome (401/403) throws `InvalidModelKeyError` and nothing is ever persisted, encrypted or not. Only `ok`/`network_error` outcomes reach the `INSERT`/`UPDATE`. The row stores `key_ciphertext`, `key_nonce`, `wrapped_dek`, and `kek_version` — never the plaintext, and the `audit_log` write records only the provider and the fingerprint, never key material. `getStatus` (`summary.ts`) reads only `provider`, `key_fingerprint`, `status`, `last_validated_at`, `last_error_code` — its return type, `ConnectionStatusView`, has no field that could carry a key.

**Decrypting on demand.** `test(ctx)` (`validate.ts`) is the one function that decrypts a stored key back to plaintext: it reads the encrypted row through `withTenant` (tenant-scoped), calls `open` with the KEK for that row's recorded `kek_version`, and holds the plaintext only in a local variable for the duration of one HTTP validation call — never logged, returned, or written. A comment guards against a rotation racing this call: `test` and the internal `recordInitialValidation` helper (called by `connect`) both re-check the row's `id` and `key_nonce` under a row lock immediately before writing a validation outcome, skipping the write rather than attaching a stale outcome to a key that was rotated out from under the call; `key_nonce` (fresh random bytes on every `seal()`) is used for this check rather than the 4-character display fingerprint, which the code notes is too collision-prone to gate a correctness check on.

**Authorization.** `connect` and `remove` require the caller's role in the account to be `owner` or `admin` (`requireOwnerOrAdmin`); `getStatus` and `test` allow any active member, but both still call `assertActiveMembership` inside the same `withTenant` transaction as the read, so a caller who is not a member of the account gets `NotFoundError` rather than `null` or another account's data.

## Data it touches

`model_connections` (key material and status), `accounts.key_broken_at` (set on a validation failure or an explicit `markBroken`, cleared on a successful re-validation — D#69, `packages/db/migrations/0606_derived_account_status.sql`: `accounts.status` is a derived column this package no longer writes directly; the database's own `accounts_derive_status` trigger computes `model_key_broken` from `key_broken_at` whenever no higher-priority marker, such as a platform hold or an owner pause, is set), and `audit_log` via the `audit_write` database function. See `../data-model.md`.

## Security notes

See `../security.md` for the platform-wide model; this package is one of the two places (alongside `@fx/runner`'s firewall-policy step) that ever holds a tenant's model key in plaintext, and both hold it only for the duration of one operation, in a local variable, never assigned to a return value or a broader scope. `connect.ts` rejects a key containing non-printable-ASCII characters or surrounding whitespace before any network call, so a key shaped in a way that could break an HTTP header is refused before it is ever encrypted or stored. `connect` also checks the requested `provider` against an exact allowed set (`ai_gateway`, `anthropic`) before doing anything else with it, so an unrecognized provider value can never reach the code path that sends a key to `api.anthropic.com`.

## Tests

Run with `pnpm --filter @fx/model-connection test` (`bash scripts/test-pg.sh`) — every suite in this package runs against a real Postgres instance via `test/globalSetup.ts`, with `fileParallelism: false` and a single forked worker (`test/toctou.test.ts` deliberately holds a row lock open across a concurrent write, which parallel files sharing the database would corrupt). `test/crypto.test.ts` covers `seal`/`open`/`fingerprintOf` directly, including the HKDF fingerprint-key derivation. `test/toctou.test.ts`, `test/w1-nonce-rotation-check.test.ts`, and `test/pool-deadlock.test.ts` cover the concurrency/rotation races described above. `test/own-cluster.test.ts` and `test/tenant-and-broken.test.ts` cover the account-status pause/restore behavior.

## Known gaps

The Anthropic provider is gated behind `isAnthropicProviderEnabled()` (`packages/model-connection/src/types.ts`), hardcoded to return `false` pending a dependency this package's own comment names as a future spike — so a tenant cannot connect an Anthropic-provider key through this package today even though the code path exists and is tested.
